# GD Store — frontend

Каркас интерфейса на React 18 + Vite, React Router, TanStack Query и Zustand. Десктопный дизайн по мотивам Slush. Игры, изображения, цены, жанры, библиотека и корзина поступают только из Django API. Встроенного каталога и демо-режима нет.

## Запуск

```sh
cd frontend
npm ci
npm run dev
```

Запустите Django на `http://localhost:8000`. Прокси Vite направляет `/api` на этот адрес. Пустой успешный ответ каталога показывает пустую витрину; при ошибке API показывается ошибка с кнопкой повторной загрузки. Без работающего бэкенда регистрация, вход и каталог не работают, но интерфейс и маршруты доступны.

Для другого API скопируйте `.env.example` в `.env.local`:

```dotenv
VITE_API_BASE_URL=https://your-backend.example/api/v1
```

Перезапустите Vite. Для отдельного домена бэкенд должен разрешать CORS. Переменные `VITE_*` публичные, секреты в них хранить нельзя. На вашем хостинге настройте SPA fallback на `index.html` и прокси `/api` к Django либо задайте полный адрес API до сборки.

## Как команда добавляет игры

1. Добавьте игру в Django Admin или другим способом на стороне бэкенда.
2. Заполните `title`, `slug`, `price`, `cover_image`, жанры и описание; выставьте `is_published=true` — текущий Django ViewSet возвращает только опубликованные записи.
3. Убедитесь, что API возвращает игру и изображения доступны по публичным URL.
4. Обновите витрину — React создаст карточки из ответа API. Менять фронтенд или пересобирать его для добавления игры не нужно.

## Контракт API

Все пути ниже относительно `/api/v1`. Клиенты находятся в `src/api/`.

| Экран       | Запрос                                                             |
| ----------- | ------------------------------------------------------------------ |
| Каталог     | GET `/catalog/games/`; `search`, `genres` (ID), `ordering`, `page` |
| Жанры       | GET `/catalog/genres/`                                             |
| Игра        | GET `/catalog/games/:slug/`                                        |
| Корзина     | GET/POST `/store/cart/`; POST `{game: id}`                         |
| Удаление    | DELETE `/store/cart/:id/`                                          |
| Заказ       | POST `/store/cart/checkout/`                                       |
| Библиотека  | GET `/library/`                                                    |
| Вход        | POST `/auth/login/`; `{username, password}`                        |
| Регистрация | POST `/auth/register/`; `{username, email, password}`              |

Каталог, корзина и библиотека используют `{results: [...]}`. Каталог также использует `count`, `next`, `previous`. Жанры поддерживают массив и пагинированный ответ. Поля карточки: `id`, `slug`, `title`, `cover_image`, `price`, `discount_percent`, `final_price`, `genres`. Подробная страница использует `short_description`, `description`, `screenshots`.

Сортировка согласована с текущим Django: `price`, `-price`, `-created_at`. Жанры передаются по ID (`genres`), не по slug. Подборки и скидки пока формируются из текущей страницы ответа; для глобальных акций и редакционных подборок нужен отдельный контракт с бэкендом.

## Регистрация

Маршрут `/register`, ссылки в шапке и форме входа. Поля: логин, email, пароль и повтор пароля. Проверяются заполнение, email, минимальные 8 символов и совпадение паролей. Повтор пароля на сервер не отправляется. Ошибки DRF `username`, `email`, `password`, `non_field_errors`, `detail` отображаются в форме. Во время запроса повторная отправка блокируется. Успех показывается только после успешного ответа API; после регистрации пользователь переходит ко входу по кнопке. JWT не выдумывается: регистрация текущего Django возвращает пользователя, вход — токены.

## Дизайн

Общие стили: `src/index.css`. Общие элементы: `src/components/`. Экраны: `src/pages/`. Минимальная ширина — 960 CSS px, сетка меняется на 1200 и 1700 px, максимальная ширина контента — 1544 px. Мобильная версия пока не реализована.

В проекте нет `.openai` и зависимости от сервиса публикации демо. Для сборки и обычного размещения нужны только npm и ваш хостинг.

## Проверка

```sh
npm run lint
npm test
npm run build
```

Тесты проверяют контракты запросов, пустой каталог, ошибки API без подстановки игр, валидацию и ошибки регистрации. Ответы API в тестах подменяются адаптером; это не проверка запущенного Django. Визуальное браузерное тестирование не выполнялось. Реальный платёжный провайдер, refresh JWT и доработка профиля остаются следующими этапами команды.
